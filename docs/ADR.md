# Architecture Decision Records

## 철학

**현업에서 Claude도 npm도 못 쓸 수 있다는 전제로 설계한다.** 편의 기능은 전부 선택 레이어로 내리고, 필수 경로는 의존성 0으로 유지한다. 어떤 결정이든 "이게 없으면 뼈대가 죽는가"를 먼저 묻는다.

---

### ADR-001: 적응형(PC/MO HTML 분리) 채택

**결정**: 반응형 단일 HTML이 아니라 PC/MO를 별도 HTML로 분리. MO 360~1023 / PC 1024~, UA 분기 임계값 1024px. 태블릿 구간(768~1023)은 MO 레이아웃을 `max-width:767px` 중앙정렬로 처리.
**이유**: 계약 요구사항이 적응형을 명시. 태블릿 전용 구간을 만들지 않은 것은 시안이 없어 근거 없는 추측이 되기 때문.
**트레이드오프**: HTML이 2벌이 되어 페이지 수정 시 두 곳을 봐야 한다. 이를 상쇄하기 위해 **SCSS·JS·컴포넌트 마크업은 단일 소스로 공유**한다. 또한 WCAG 1.4.10(Reflow) 위험이 있어 PC CSS에도 1024px 미만 축소 대응을 최소한으로 넣는다.

### ADR-002: 번들러를 필수가 아닌 선택 레이어로

**결정**: Vite를 쓸 수 있게 두되, 없어도 전부 동작하도록 네이티브 ES Module + 컴파일된 CSS 직참조를 기본 경로로 삼는다.
**이유**: 요구사항이 번들러를 금지하지는 않는다("Vanilla JavaScript ES6+"는 프레임워크 배제이지 빌드 스텝 금지가 아니며, 대상 브라우저가 최신 2버전뿐이라 레거시 트랜스파일도 불필요). 그러나 **현업이 폐쇄망이라 `npm install`이 막히면 번들러 의존 시 뼈대가 통째로 죽는다.**
**트레이드오프**: HMR 같은 개발 편의를 기본으로 누리지 못한다. 대신 `tools/serve.js` 로 최소 개발 서버를 자체 제공한다.

### ADR-003: SCSS 채택 + dart-sass 바이너리 동봉

**결정**: SCSS를 쓰되 3중 안전망을 건다 — ① `npm install sass` ② `tools/vendor/sass/` 단독 실행 파일 ③ **컴파일된 CSS를 커밋**.
**이유**: SCSS의 mixin·모듈화는 퍼블리싱 실무 표준이고, 단일 CSS로 컴파일되면서 네이티브 `@import` 순차 로딩 성능 문제까지 해소된다. dart-sass가 Dart AOT 단독 바이너리로 배포되어 npm 없이도 실행 가능한 것이 이 결정을 가능하게 했다.
**트레이드오프**: 컴파일 산출물을 커밋하므로 diff 노이즈가 생긴다. 바이너리는 OS 종속이라 현업 OS가 다르면 별도 수급이 필요하다. 3계층 안전망이 이 경우를 받아낸다.

### ADR-004: 토큰을 SCSS 변수가 아닌 CSS Custom Properties로 출력

**결정**: 색·타이포·간격을 `$var` 가 아니라 `--var` 로 정의한다. SCSS 변수는 미디어쿼리 브레이크포인트처럼 CSS 변수를 쓸 수 없는 자리에만.
**이유**: **개발사가 SCSS 컴파일 체인 없이 값을 수정할 수 있어야 한다.** 이관 후 색상 하나 바꾸겠다고 개발사가 dart-sass를 설치하는 상황을 막는다. 런타임 테마 전환 여지도 확보된다.
**트레이드오프**: SCSS의 컴파일 타임 색상 연산(`darken()` 등)을 쓸 수 없다. `color-mix()` 같은 네이티브 CSS 기능으로 대체한다.

### ADR-005: WCAG 2.1 AA를 3중으로 검증

**결정**: ① `check.js` 가 색상 토큰 대비를 계산해 4.5:1 미만이면 빌드 실패 ② `guide.html` 에서 axe 자동 실행 ③ 수동 체크리스트(키보드 순회·포커스 표시·확대 200%·스크린리더).
**이유**: axe 같은 자동 도구는 WCAG 위반의 일부만 검출한다. 특히 색상 대비는 **토큰 설계 단계에서 잡는 것이 가장 싸다** — 시안이 없는 지금 기준을 박아두면 나중에 시안 색상을 넣을 때 위반이 즉시 드러난다.
**트레이드오프**: 대비 검사가 `@contrast` 주석 선언에 의존하므로 선언을 빠뜨리면 검사되지 않는다. 선언 누락은 경고로 알린다.

### ADR-006: Storybook을 채택하지 않고 카탈로그를 자동 생성

**결정**: Storybook·Fractal·KSS 등 스타일가이드 도구를 쓰지 않는다. 컴포넌트 fragment의 `@component` 주석을 `build.js` 가 파싱해 `guide.html` 과 `.code-snippets` 를 생성한다.
**이유**: 폐쇄망 이전에 **프로젝트 성격이 맞지 않는다.** Storybook의 핵심 가치는 props 조합 폭발을 다루는 것인데, CSS 클래스 기반 컴포넌트에는 그 문제가 없다. 더 결정적으로 마크업이 이미 `assets/components/` 에 단일 소스로 있는데 `*.stories.js` 가 그것을 다시 감싸면 **이중 관리**가 생긴다. 대안 도구들도 전부 npm 의존이라 폐쇄망 관점에서 동급이다.
**트레이드오프**: 인터랙션 테스트·비주얼 회귀 같은 Storybook 생태계 기능을 포기한다. 대신 의존성 0, 컴포넌트 추가 시 자동 반영, 개발사에 그대로 넘길 수 있는 산출물을 얻는다.

### ADR-007: 훅 판정 로직을 에이전트 설정 밖에 둔다

**결정**: `.claude/settings.json` 과 `.codex/hooks.json` 은 **배선만** 한다. 판정 로직은 `scripts/hooks/` 의 Node 스크립트에 두고, 두 에이전트가 같은 파일을 호출한다. 훅 스크립트 자신은 TDD 강제 대상에서 제외하되, `tools/check.js` 가 `scripts/hooks/**/*.test.js` 를 **`src/` 가 없는 시점에도** 항상 돌려 대신 막는다.
**이유**: 훅이 깨지면 조용히 통과한다 — 이 저장소는 이미 그 사고를 겪었다(`jq` 부재로 TDD 가드가 무력화). Codex 이관 때도 같은 일이 재발했다: 셸 도구가 `command` 를 argv **배열**로 보내는데 문자열만 받고 있었고, `Edit`·`Write` 페이로드의 `file_path` 를 아무도 읽지 않아 가드가 한 번도 발동하지 않았다. 로직이 에이전트 설정 안에 인라인으로 있으면 이런 회귀를 테스트로 잡을 수 없다.
**트레이드오프**: 훅 파일이 배선과 로직 두 곳으로 나뉜다. 대신 `.claude/` 와 `.codex/` 를 둘 다 지워도 `node tools/check.js` 로 동일한 기준이 남는다.

### ADR-008: Codex 실행을 workspace-write 샌드박스로 고정

**결정**: `scripts/execute.py` 는 `codex exec --sandbox workspace-write --dangerously-bypass-hook-trust` 로 step 을 돌린다. 승인 우회(`--dangerously-bypass-approvals-and-sandbox`)는 쓰지 않는다.
**이유**: 하네스는 무인으로 20개 step 을 도는데, 샌드박스까지 해제하면 작업 트리 밖을 건드리는 사고를 막을 장치가 없다. 훅 신뢰만 우회하는 이유는 별개다 — Codex 는 신뢰 등록이 안 된 훅을 실행하지 않고 `exec` 는 비대화형이라 신뢰를 물을 수 없어서, 이 플래그가 없으면 **안전 훅이 통째로 빠진 채** step 이 돈다. 훅 소스는 저장소 안에 있고 테스트로 검증되므로 우회 대상으로 적절하다.
**트레이드오프**: `workspace-write` 는 **네트워크가 기본 차단**이다. `npm install` 이 필요한 step 은 실패한다. Tier 0 원칙상 그런 step 이 있으면 안 되므로, 이 실패는 버그가 아니라 신호로 취급한다.

### ADR-009: 훅 명령을 셸 인용에 의존하지 않는 형태로 쓴다

**결정**: `.codex/hooks.json` 의 `commandWindows` 는 `node scripts/hooks/codex-hook.js <mode>` 처럼 **따옴표도 변수 확장도 없는 한 줄**로 적는다. PowerShell 래퍼와 `$(git rev-parse --show-toplevel)` 같은 경로 계산을 넣지 않는다.

**이유**: 이 저장소가 같은 사고를 **세 번** 겪었다. ①`jq` 부재로 TDD 가드 무력화 ②셸 도구가 `command` 를 argv 배열로 보내는데 문자열만 받아 검사 통과 ③`commandWindows` 의 중첩 이스케이프(`\\\"`)가 cmd.exe 를 거치며 깨져 **훅 프로세스가 아예 실행되지 않음**. 세 번째가 특히 나쁘다 — Codex 는 훅 실행 실패를 `hook: PreToolUse Failed` 로 찍고 **그대로 작업을 진행**한다. 차단 로직이 정확해도(단독 실행 시 exit 0 에 올바른 deny JSON) 아무것도 막지 못했다. 훅이 붙었는지는 로그의 `Blocked`/`Completed` 로만 판별할 수 있고 `Failed` 는 조용한 무력화를 뜻한다.

경로 계산이 필요 없는 이유는 Codex 가 훅을 저장소 루트를 cwd 로 실행하기 때문이고, 판정 스크립트 자신이 `findRepoRoot(cwd)` 로 다시 위치를 잡으므로 상대 경로로 충분하다.

**트레이드오프**: cwd 가 저장소 루트라는 전제에 기댄다. 그 전제가 깨지면 훅이 다시 조용히 빠지므로, 훅 배선을 바꾼 뒤에는 반드시 프로브로 `Blocked` 를 눈으로 확인한다.

### ADR-010: Windows 에서 codex 샌드박스를 unelevated 로 고정

**결정**: `sys.platform == "win32"` 일 때 `execute.py` 가 `-c windows.sandbox="unelevated"` 를 붙인다. 사용자의 `~/.codex/config.toml` 은 건드리지 않는다.

**이유**: 기본값 `elevated` 는 `CreateProcessWithLogonW` 로 다른 사용자 컨텍스트에서 프로세스를 띄우는데, 이게 실패하면(`failed: 2`) codex 의 **파일 쓰기와 셸 실행이 전부** 죽는다. step 은 아무것도 만들지 못한 채 3회 재시도만 돌다 `error` 로 끝난다. 증상이 "codex 가 일을 안 한다" 로만 보여 원인 추적이 비싸다. `unelevated` 도 샌드박스는 그대로 유지하므로 ADR-008 의 "승인 우회는 쓰지 않는다" 와 충돌하지 않는다.

**트레이드오프**: 사용자 전역 설정을 덮어쓰므로, 의도적으로 `elevated` 를 쓰는 환경에서도 하네스 실행 중에는 무시된다. 저장소 밖 설정에 하네스가 좌우되지 않는 편이 낫다고 판단했다.
